# SEO/GEO: эксплуатация и измерение

Найм и консалтинг имеют равный приоритет. Установки SheSafe — отдельная цель.

## Локальные доступы

- `.env`: client ID/secret Яндекса, OAuth access/refresh tokens, GSC property и путь Google credentials. `.secrets/gsc-service-account.json`: ключ сервисного аккаунта. Не включать ни один из этих файлов в Git, Docker, Vite или публичный отчёт.
- GSC и Яндекс API проверены чтением реальных данных. Client secret Яндекса сам по себе не авторизует Webmaster API.
- Текущий скрипт использует сохранённый access token. При его истечении обновить через официальный OAuth token endpoint с refresh token и атомарно заменить локальные значения; не вставлять токены в аргументы CLI или логи.
- GA4: запрос Admin API вернул `SERVICE_DISABLED`. Нужны включённые Analytics Admin/Data API и доступ сервисного аккаунта к конкретному GA4 property. Наличие доступа GSC не даёт доступа GA4.

## Поисковые данные

`npm run seo:baseline` сохраняет 90 дней окончательных данных GSC, срезы страниц/запросов/стран/устройств, URL Inspection, sitemap и диагностику Яндекса в `seo/private/search-baseline.json`.

Период по умолчанию заканчивается три дня назад. Даты GSC относятся к Pacific Time. Итоги запрашиваются отдельно от строк с запросами: анонимизация может исключить запросы из детализации. `truncated` относится к лимиту нашего экспорта, а не гарантии полного раскрытия данных Google. Popular queries Яндекса — ограниченный список, не полный спрос. Длинные запросы с операторами исключения сайтов нельзя без дополнительной проверки считать человеческим коммерческим спросом.

После публикации: `npm run seo:live -- --output seo/live-after-release.json`, затем `.venv-seo/bin/python scripts/search_baseline.py --submit-sitemap`. Успешная отправка sitemap не означает индексацию. Повторная инспекция — через 2–4 недели, особенно Insights и языковых версий SheSafe.

## Контактные события

- `click-gcal-hiring` — намерение обсудить роль.
- `click-gcal-consulting` — намерение обсудить задачу роста.
- Оба ведут в действующий календарь с одинаковым визуальным приоритетом. Метрики не объединять в одну оценку качества лида.
- Один клик не равен записи, состоявшемуся звонку, квалифицированному обращению или выручке. Подтверждённые результаты записывать вручную отдельно, без персональных данных в репозитории.
- Worker сохраняет полученное событие в отдельный `event2:` KV key с 180-дневным TTL; случайный UUID — идентификатор приёма, не посетителя. Старые `event:` counters читаются для истории, но могут недосчитывать конкурентные события.
- Источник — укрупнённая категория referrer: Google, Яндекс, Bing, AI, direct, referral. Google AI Overview остаётся Google; отсутствие referrer выглядит как direct. Атрибуция между страницами поддерживается sessionStorage в той же вкладке, окно неактивности 30 минут.
- `npm run analytics:events -- --days 30` выдаёт дату, событие, страницу, источник и число принятых событий. Это не сессии/уникальные люди; боты, повторы и тестовые запросы возможны.

## AI pilot и производительность

`npm run seo:geo` — 12 фиксированных вопросов × 3 независимых запроса Gemini API с поисковым инструментом. Есть ограничение частоты; успешные ответы возобновляемый запуск не запрашивает повторно. Фиксируются модель, параметры, дата, текст, реально выполненные поиски, источники и причина завершения. Брендовые и небрендовые вопросы оцениваются отдельно. Неуспех API или обрезанный ответ — не отсутствие видимости.

Google возвращает часть цитат через redirect URL. Пока конечный адрес не разрешён, нельзя считать отсутствие прямого `boonts.com` в URI отсутствием цитирования. API pilot не измеряет пользовательские интерфейсы Gemini, ChatGPT, Perplexity или AI Overviews. Следующий повтор — через четыре недели после выпуска, с теми же параметрами и отдельным учётом смены модели.

PageSpeed API вернул 429; Lighthouse CLI выполнен отдельно. Лабораторный LCP/TBT не равен полевому CWV/INP. Результаты Lighthouse зависят от сети, устройства и сторонних скриптов; сравнивать одинаковые URL, режим и версию. CrUX требует достаточной полевой выборки; отсутствие отчёта не означает прохождения CWV.

## Что требует владельца

1. Проверяемый кейс: период, определение результата, метод оценки, личная роль, пересечение эффектов и разрешённые доказательства. `$100M+`, ARR и P&L не возвращать без уточнения.
2. Даты опыта для проверки `7+ years` и актуальность публичных профилей.
3. Актуальная доступность SheSafe в App Store, требования ОС, стоимость и реальные гарантии безопасности. Непроверенные числовые/шифровальные обещания убраны из разметки; политику конфиденциальности нельзя считать техническим аудитом приложения.
4. Квалификация реальных обращений и итогов разговоров по двум направлениям.
